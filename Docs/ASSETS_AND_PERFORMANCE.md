# Asset and performance plan

## Asset production

All geometry generated by this project is original source-built blockout art. Engine primitives are engine content. No downloaded vehicle model, music, logo, map or character is used. Add any acquired content to a provenance manifest with author, source URL, acquisition date, license text, redistribution conditions and modifications before import.

The initial SM5 sky light uses Unreal's `DaylightAmbientCubemap`, tinted and attenuated for night readability. It is a temporary ambient/reflection probe, not a captured Nova City environment. Replace it with an authored local probe during the art pass. Generated exterior glass is opaque and single-sided; the cockpit currently looks through its culled backfaces.

| Asset | Phase 1 source | Production replacement and acceptance |
|---|---|---|
| Aster S6 exterior | Sculpted procedural body, separate wheels/lights/glazing | Artist-authored original coupe, clean normals, panel gaps, four LODs, separated customization anchors; inspect closeups in day/night |
| Interior | Basic visible cabin | Left-seat camera envelope, wheel animation, illuminated instruments, cockpit occlusion; readable at native resolution |
| Vehicle collision | Simple Chaos chassis + wheel contacts | Convex hull validated against walls, curb heights and rollover; presentation never drives collision |
| Car materials | Generated paint/glass/rubber/metal | Layered clearcoat, normals and calibrated roughness; glass sorting, wetness/dirt masks |
| District | Instanced roads, buildings, props | Modular curb/corner/junction kit, distinct landmarks, trim sheets, signage; no gaps in road collision |
| Environment | Night lighting, fog, wet-looking asphalt | Authored lighting and weather/VFX, calibrated exposure, distant skyline HLOD |
| Sound | Original procedural engine | Licensed or original load/coast intake/exhaust recordings across RPM bands; loops without clicks |
| UI | Engine fonts and canvas HUD | Original typography/icon system, localization, safe areas, colorblind readability, scalable layouts |

Working budgets for the hero car: 100–180k exterior triangles at closest driving LOD, up to 100k cockpit triangles only when needed, 4 material families using instances, 2K maps for standard exterior sets, selective 4K only after measured benefit. These are proposed budgets, not measurements of the generated mesh. Production car doors/interior parts need authored pivots and collision rules. Road art needs tileable asphalt/paint/wetness material families and decals that do not shimmer at speed.

## Performance targets

Target 60 FPS at 1080p on a named midrange PC once hardware is measured. Benchmark CPU and GPU independently; 16.67 ms is the complete frame budget, not 16 ms for each serial task. Suggested CPU budgets: vehicle/contact logic ≤1 ms, AI/traffic ≤2 ms, world scheduling ≤1 ms, main/render submission each leaving ≥25% headroom. GPU target ≤14 ms at the selected output/upscale quality. Do not promise a target from configuration values.

| Preset | Initial rendering policy | Acceptance |
|---|---|---|
| Low | Lower resolution scale, conventional shadows, reduced fog and effects; fallback GI/reflections | Drivable streets remain readable; no physics/input reduction |
| Medium | Balanced shadows/reflections, moderate view distance | 60 FPS budget on target low-mid hardware |
| High | Lumen and virtual shadows where supported, moderate fog | Baseline art presentation with bounded overlapping lights |
| Ultra | Higher lighting/shadows/reflections, longer decorative culling distance | Frame-time budget documented against reference hardware |
| Cinematic | Capture-oriented quality with explicit cost | Photo/replay use; no competitive advantage |

Phase 1 ships standard Unreal scalability defaults and developer controls. Detected development hardware is an i5-6440HQ and NVIDIA 940MX with 2GB VRAM, so the initial configuration is 1280×720 windowed, 85% screen percentage, DX11/SM5, conventional shadows and SSR. This is a compatibility starting point; 60 FPS on this laptop is not promised. The settings menu now exposes Low through Cinematic engine scalability presets, resolution scale, frame cap, VSync and motion blur; visual/performance acceptance of every preset remains pending. Full resolution/display-mode rollback, capability filtering, upscaling/frame generation and hardware ray tracing controls remain pending. Motion blur defaults off. No inaccessible fake setting toggles are shown.

Use `stat unit`, `stat gpu`, `stat RHI`, `stat memory`, `stat physics`, `stat streaming`, `profilegpu` and Unreal Insights traces. Add CPU trace scopes to contacts/world generation. Capture warmed 120-second runs, report median/p95/p99 and worst frame, route, build, resolution, preset, CPU/GPU, driver, RAM and VRAM. Compare 30/60/120 FPS with fixed input maneuvers separately from performance runs. Never interpret NullRHI headless timings as rendering performance.

Repeated geometry uses hierarchical instances. Disable collision and shadow casting on cosmetic lights/windows. Bound shadowed light overlap, volumetric resolution, particles and texture residency. Static district generation has no tick. Later traffic uses near/mid/far update rates and pooled actors; far traffic remains road-graph state. Preallocate race/replay buffers, batch audio parameter delivery and avoid allocations in wheel loops.

Streaming validation in Phase 6 includes cold cache, high speed, 180-degree turns, fast travel and low disk throughput. Road collision must load before reachable space; prefetch by velocity and measured load latency. Track memory over repeated district crossings and report peak/resident GPU textures. Generate HLODs offline; Nanite assets must have a supported material path and measured scene benefit.
